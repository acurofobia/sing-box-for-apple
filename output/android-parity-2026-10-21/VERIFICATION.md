# Проверка подготовленной спецификации

Обновление публикации 25 октября 2026: Sketch и ZIP-копии исключены из GitHub; PNG, JSON и исходники эталонов сохранены. Манифесты и проверки обновлены для публикуемого комплекта. Ниже сохранены результаты исходной подготовки от 21 октября.

Дата: 21 октября 2026 года, Asia/Yekaterinburg. Объект проверки — документы и передаваемые эталоны. Реализация Android по этой спецификации ещё не выполнялась.

## Источники и целостность

- Исходный android-handoff-2026-10-20.zip: проверены 126 файлов по manifest, JSON, 11 состояний в PNG 1x/2x, layouts и CRC Sketch. Проверка tools/verify_package.py завершилась с кодом 0.
- Все 44 файла applicationSource старого Android совпали с его dist/build-manifest.json. Версия и toolchain в спецификации описывают этот baseline.
- Общие файлы из исходного reference/ios-source совпали с текущими соответствующими файлами рабочего дерева. Дополнительно сохранены отсутствующие там runtime/core исходники и тесты.
- Зафиксированы HEAD приложения, core и TURN, SHA-256 оригинального архива, старой спецификации, незакоммиченных входов и 101 дополнительного source snapshot.

## Текущий роутинг и DNS

Выполнено `python3 -m unittest discover -s scripts/tests -p test_prototype_routing.py -v` в исходном sing-prototype. Результат: 14 tests, OK, включая локальный native-core/DoH integration.

Первая попытка в песочнице дала 13 успешных проверок и ошибку доступа при bind loopback-порта. Повторный запуск с разрешением локальных listener завершился успешно. Изменять код приложения для обхода этой ошибки не потребовалось. Тест использует искусственные loopback DNS/proxy endpoints и не устанавливает системный VPN/TUN.

Этот результат проверяет текущий эталон DNS/routing, а не Android-перенос.

## Проверка полноты требований

Спецификация содержит 72 уникальных REQ-ID и 23 раздела. ACCEPTANCE.csv содержит 93 уникальных сценария, покрывающих все 72 требования; исходные статусы всех сценариев not-run. У каждого предусмотрены шаги, ожидаемый результат и требуемое доказательство.

Независимый Builder Check сопоставил спецификацию с исходниками. По его замечаниям уточнены legacy UI Bearer на явно указанном отдельном origin и обязательная видимость самого block04 для доступности режима. Повторная проверка подтвердила устранение существенных неоднозначностей.

## Границы проверки

Старый Android-проект использовался только для чтения. Его исходники, настройки, secrets, APK и AAR не изменялись. Новые Android APK/AAR не собирались, эмулятор и телефон в этой работе не запускались. Реальные VPN-соединения, SRTP interoperability, Doze и аппаратная память по новой спецификации не проверены. Для них предусмотрена будущая приёмка, и они не отмечены выполненными.

Передача завершается отдельной проверкой tools/verify_bundle.py и CRC итогового ZIP. Они проверяют целостность комплекта и покрытие требований; результаты не подменяют испытания приложения.
