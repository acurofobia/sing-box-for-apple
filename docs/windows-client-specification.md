# Спецификация Windows клиента на основе sing-box

Дата: 16 октября 2026 года. Версия требований: 1.0.

Разработать Windows-приложение, похожее по сценариям и логике на основное приложение из `PrototypeApp/` передаваемого репозитория. Пользователь вставляет `vless://` ссылку, сохраняет сервер, выбирает встроенный роутинг и подключает VPN. Сетевое ядро — официальный sing-box. Встроенные правила и их автоматическое обновление должны работать без сервера подписок.

В интерфейсе сохранить переключатель **VLESS / VK TURN**. VLESS работает; VK TURN виден, недоступен для выбора и подписан **«В разработке»**. Реализация транспорта VK TURN в первую версию не входит.

Документ передаётся исполнителю вместе с исходным кодом Apple-приложения. Он задаёт требования к новой Windows-реализации; менять работающее Apple-приложение для выполнения этой задачи не требуется.

## Объём первой версии

Обязательные возможности:

- Установка и запуск на Windows 10 22H2 x64 и Windows 11 x64. Это целевая матрица тестирования приложения; ARM64 и x86 в первую версию не входят.
- Русский интерфейс, разделы «VPN», «Роутинги» и просмотр журнала.
- Один сохранённый VLESS-сервер: импорт ссылки из текстового поля или буфера обмена, просмотр кратких сведений, замена и удаление.
- Системный VPN через TUN, а не только HTTP/SOCKS-прокси для отдельных приложений.
- Два встроенных режима маршрутизации: **«С роутингом»** и **«Russia inside»**. По умолчанию выбран первый.
- Автоматическое обновление списков активного режима через VLESS, постоянный кэш и встроенные списки для первого запуска.
- Подключение, отключение, отображение состояния, работа в системном трее и понятные сообщения об ошибках.
- Сохранение сервера и выбранного роутинга между запусками.

В первую версию не входят сервер и клиент подписок, аккаунты, биллинг, загрузка конфигурации по HTTP(S)-ссылке, список из нескольких серверов, автоматический выбор сервера, QR-импорт, редактор пользовательских правил, импорт полного sing-box JSON, автоматическое обновление приложения или ядра, kill switch и автоматическое подключение при входе в Windows. Обновление `.srs` входит в объём и не является подпиской.

## Техническое решение

### Выбор стека

Рекомендуемый стек: C#, .NET 10 LTS, WPF и MVVM для интерфейса; Windows Service для привилегированных операций; официальный `sing-box.exe` отдельным процессом. Сборка поставляется self-contained, чтобы пользователю не требовалась отдельная установка .NET. Основание для выбора: приложение предназначено только для Windows, а служба, трей и локальные разрешения являются основной частью интеграции. См. [.NET 10](https://learn.microsoft.com/en-us/dotnet/core/whats-new/dotnet-10/overview) и [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/).

Варианты, которые не выбираются для первой версии: Tauri требует дополнительного веб-стека и той же отдельной службы для TUN; встраивание Go-ядра через собственный ABI увеличивает объём межъязыковой интеграции. При любом стеке поведение из документа обязательно.

### Компоненты и границы

1. **Desktop UI** работает без прав администратора, хранит зашифрованный профиль пользователя, показывает состояние службы и отправляет типизированные команды.
2. **Windows Service** повторно валидирует данные, собирает окончательный JSON из доверенных шаблонов, проверяет его закреплённым ядром, запускает и останавливает единственный процесс sing-box. Служба является источником фактического состояния подключения.
3. **sing-box** обслуживает TUN, VLESS, DNS, правила, загрузку remote rule-set и постоянный кэш. Собственный сетевой движок и отдельный загрузчик списков не создавать.

Связь UI и службы — локальный named pipe с версией протокола, идентификатором запроса и проверкой SID клиента. Команды: `GetState`, `Connect`, `Disconnect`, `SetRoutingMode`, `SubscribeEvents`. `Connect` получает нормализованный профиль и идентификатор режима, а не путь к произвольному файлу или командную строку. Состояние и события не возвращают UUID и другие секреты профиля.

Первая версия обслуживает одного владельца установки: SID владельца фиксируется установщиком; управлять VPN могут этот пользователь и администраторы. Одновременные подключения разных Windows-пользователей не поддерживаются. Служба запускается с достаточными правами для TUN; при использовании LocalSystem все входные команды ограничиваются перечисленным контрактом.

Путь к ядру и рабочая директория задаются установкой. UI не может передать службе произвольный исполняемый файл, shell-команду, URL обновления списков, `detour` или произвольную секцию JSON. Изменяемые файлы не размещать рядом с исполняемыми файлами в Program Files.

## Интерфейс и пользовательские сценарии

### Экран VPN

- Переключатель «VLESS» / «VK TURN». VLESS выбран по умолчанию даже без профиля. У VK TURN постоянно видна пометка «В разработке»; элемент недоступен для мыши и клавиатуры, имеет соответствующее состояние доступности и текст для screen reader.
- VK TURN не открывает форму импорта, не меняет выбранный режим, не отключает действующий VPN и не запускает сетевые запросы. В службе попытка выбрать его также отклоняется как `UnsupportedConnectionMode`.
- Карточка VLESS: имя из ссылки, адрес, порт, транспорт, TLS/Reality; UUID и исходную ссылку постоянно не показывать.
- Кнопки «Вставить ссылку», «Импортировать», «Удалить сервер», «Подключить» / «Отключить» и переход к журналу.
- До импорта: «Добавьте VLESS-ссылку для подключения», кнопка подключения недоступна. Буфер обмена читается только после нажатия пользователем.
- При замене профиля сначала показать краткие сведения нового сервера; существующий профиль заменить только после успешной проверки и сохранения. Ошибка не удаляет рабочий профиль.
- Импорт, замена и удаление доступны только при отключённом VPN. Во время переходных состояний исключить повторные и конфликтующие действия.

### Состояния подключения

Использовать состояния `Disconnected`, `Connecting`, `Connected`, `Reconnecting`, `Disconnecting`, `Error`; недоступность службы отображать отдельно. После открытия окна UI запрашивает состояние службы, а не предполагает, что VPN выключен.

`Connected` означает: ядро успешно запущено, TUN и маршруты установлены. Для готовности служба должна получить сообщение завершения запуска закреплённого ядра и проверить средствами Windows наличие своего активного TUN-интерфейса, маршрутов и DNS-настроек. Одного PID недостаточно. Это состояние не доказывает доступность удалённого VLESS-сервера; ошибки соединения с ним показывать отдельно.

Подключение и отключение должны допускать отмену и иметь конечные тайм-ауты: до 30 секунд на запуск и до 15 секунд на остановку. По истечении срока показать ошибку и выполнить очистку принадлежащих приложению сетевых ресурсов. Не оставлять UI бесконечно в состоянии ожидания.

Смена роутинга при активном VPN выполняет одно последовательное переподключение. При выключенном VPN только сохраняет выбор. Если новый запуск не удался, вернуть прежний выбранный режим и один раз попытаться восстановить предыдущее подключение; при повторной ошибке остановиться и явно показать состояние. Не запускать бесконечный цикл восстановления.

### Трей и завершение работы

Закрытие окна сворачивает приложение в трей; при первом таком действии показать пояснение. Меню трея содержит «Открыть», «Подключить» / «Отключить», «Выход». Явный выход отключает VPN и завершает UI. Повторный запуск открывает существующий экземпляр.

Закрытие окна и авария UI не должны сами по себе уничтожать VPN, которым владеет служба. Повторно открытый UI восстанавливает отображение из службы. Выход пользователя из Windows завершает сессию VPN; после перезагрузки самоподключения нет. При остановке или аварии службы дочерний процесс не должен оставаться бесконтрольным.

## Импорт VLESS

### Формат и валидация

Принимать одну ссылку вида `vless://UUID@host:port?parameters#name`. Разрешены пробелы и переносы только вокруг ссылки. Несколько ссылок, HTTP(S)-подписка, JSON и другие схемы отклоняются с объяснением поддерживаемого формата. Ограничить ввод 16 КиБ.

Обязательно проверить UUID, непустой host и целочисленный порт 1–65535. Поддержать доменное имя, IPv4 и IPv6 в квадратных скобках; имя сервера нормализовать средствами URI/IDN, не выполнять DNS-запрос во время импорта. Пароль в userinfo, управляющие символы, некорректное percent-encoding и повторяющиеся query-параметры отклонять.

Query разбирать до percent-decoding значений; декодировать ровно один раз. Символ `+` сохранять как `+`, не преобразовывать в пробел по правилам HTML-форм. Фрагмент декодировать как имя; при его отсутствии использовать `host:port`. Имя — только отображаемый текст, оно не определяет пути и теги конфигурации.

### Поддерживаемые варианты

| Параметр ссылки | Правило первой версии и отображение в sing-box |
| --- | --- |
| `encryption` | Отсутствует или `none`; другое значение отклонить |
| `type` | Отсутствует / `tcp`, `ws`, `grpc`; другие транспорты отклонить |
| `security` | Отсутствует / `none`, `tls`, `reality` |
| `flow` | Пустой либо `xtls-rprx-vision`; Vision разрешён только с TCP и TLS/Reality |
| `sni` | `tls.server_name`; для обычного TLS без `sni` использовать доменный host, а для IP проверять IP сертификата |
| `fp` | `tls.utls.enabled` и `fingerprint`; проверять по значениям закреплённого ядра; без параметра для TLS использовать штатный TLS, для Reality — `chrome` |
| `alpn` | Список через запятую → `tls.alpn`; применим только при включённом TLS |
| `pbk` | `tls.reality.public_key`; обязателен для Reality, base64url ключ длиной 32 байта после декодирования |
| `sid` | `tls.reality.short_id`; допускается пустое значение либо hex чётной длины до 16 символов |
| `path` | Для WS → `transport.path`, по умолчанию `/` |
| `host` | Для WS → `transport.headers.Host`; не заменяет адрес подключения и TLS SNI |
| `serviceName` | Для gRPC → `transport.service_name`; отсутствие означает пустое имя сервиса |
| `headerType` | Отсутствует или `none`; маскировки TCP не реализовывать |

TCP использует отсутствие `transport` в outbound; не генерировать `transport.type: tcp`. Для WS генерировать `transport.type: ws`, для gRPC — `grpc`. Не присваивать `network: tcp` только из-за `type=tcp`: транспорт ссылки и разрешение TCP/UDP трафика — разные поля. UDP сохраняется доступным с поддерживаемым ядром packet encoding; использовать штатное значение sing-box, без самодельной упаковки.

Для первой версии Reality поддерживается только поверх TCP и требует явно заданного `sni` и `pbk`. Поля TLS при `security=none`, WS-поля при TCP и другие несовместимые комбинации отклонять. Не включать `tls.insecure`. Ссылки с `allowInsecure`, `insecure`, `spx`, `mode`, `xhttp`, `splithttp`, `kcp`, `quic` или другими неперечисленными параметрами/значениями отклонять сообщением с именем неподдерживаемого параметра, без его секретного значения. Не превращать неподдерживаемый транспорт в TCP молча.

Это контракт импортера приложения, а не утверждение о едином официальном стандарте VLESS URI. Структуру получаемого outbound сверять с [VLESS outbound](https://sing-box.sagernet.org/configuration/outbound/vless/), [TLS](https://sing-box.sagernet.org/configuration/shared/tls/) и [V2Ray transport](https://sing-box.sagernet.org/configuration/shared/v2ray-transport/) закреплённой версии ядра.

Пример тестовой ссылки без действующих учётных данных:

```text
vless://bf000d23-0752-40b4-affe-68f7707a9661@example.org:443?encryption=none&type=ws&security=tls&sni=example.org&host=example.org&path=%2Fvpn#Test%20server
```

Соответствующий outbound:

```json
{
  "type": "vless",
  "tag": "proxy",
  "server": "example.org",
  "server_port": 443,
  "uuid": "bf000d23-0752-40b4-affe-68f7707a9661",
  "tls": {
    "enabled": true,
    "server_name": "example.org"
  },
  "transport": {
    "type": "ws",
    "path": "/vpn",
    "headers": { "Host": "example.org" }
  },
  "domain_resolver": { "server": "bootstrap", "strategy": "ipv4_only" }
}
```

Пример показывает один outbound, а не полный запускаемый конфиг. После нормализации служба собирает полный конфиг и выполняет `sing-box check -c <config-path>`. Проверка синтаксиса не проверяет доступность сервера или правильность его учётных данных.

## Встроенная маршрутизация

### Общие правила переноса

Источники правил — передаваемые `PrototypeApp/routing.json` и `PrototypeApp/RuleSets`. Сохранять порядок бизнес-правил, состав списков, условия и действия. Во всей генерируемой конфигурации заменить исторический outbound `vk-wg` на `proxy`: в правилах, `route.final`, DNS и загрузке rule-set. Outbound `direct` сохранить. Строковая замена по всему JSON недопустима; изменять соответствующие поля структуры.

Редактор правил и пользовательские URL не нужны. Теги `geosite-*` и `geoip-direct` обозначают `.srs` rule-set, а не устаревшие базы `geosite.db` / `geoip.db`.

### Режим С роутингом

Идентификатор `roscomvpn`, выбран по умолчанию. Порядок правил из исходного файла:

| Порядок | Условие | Действие |
| --- | --- | --- |
| 1 | Входящий трафик | `sniff` |
| 2 | DNS | `hijack-dns` |
| 3 | `8.8.8.8/32` или `77.88.8.8/32`, порт 443 | `direct` |
| 4 | `geosite-youtube`, UDP, порт 443 | `reject` |
| 5 | `geosite-google-play`, `geosite-github`, `geosite-twitch-ads`, `geosite-youtube`, `geosite-telegram` | `proxy` |
| 6 | `geosite-win-spy`, `geosite-torrent`, `geosite-category-ads` | `reject` |
| 7 | `geosite-private`, `geosite-category-ru`, `geosite-whitelist`, `geosite-microsoft`, `geosite-apple`, `geosite-epicgames`, `geosite-riot`, `geosite-escapefromtarkov`, `geosite-steam`, `geosite-twitch`, `geosite-pinterest`, `geosite-faceit` | `direct` |
| 8 | Частные IP-адреса | `direct` |
| 9 | `geoip-direct` | `direct` |
| По умолчанию | Трафик без совпадения | `proxy` |

Не упрощать этот режим до «российское напрямую, остальное через VPN»: порядок пересекающихся списков влияет на результат. Источник всех 21 URL — `routing.json`. Репозитории списков: [roscomvpn-geosite](https://github.com/hydraponique/roscomvpn-geosite) и [roscomvpn-geoip](https://github.com/hydraponique/roscomvpn-geoip).

### Режим Russia inside

Идентификатор `russiaInside`. После `sniff` и `hijack-dns` направлять совпадения списка `russia-inside` в `proxy`; `route.final` — `direct`. Другие бизнес-правила RoscomVPN, включая блокировки и специальные списки direct, в этом режиме не добавлять.

Источник: [itdoginfo/allow-domains](https://github.com/itdoginfo/allow-domains). URL бинарного списка:

```text
https://github.com/itdoginfo/allow-domains/releases/latest/download/russia_inside.srs
```

Начальный файл — `PrototypeApp/RuleSets/russia-inside.srs`. Включить `dns.reverse_mapping: true`, чтобы учитывать домены из DNS-ответов для трафика, который не удалось распознать sniffing. Это не гарантирует распознавание домена для произвольного IP или собственного зашифрованного DNS приложения.

### Экран Роутинги

Показать переключатель двух режимов, краткое описание выбранного поведения, интервал «Раз в сутки», путь загрузки «Через VLESS» и пояснение о кэше/встроенных списках. Отдельно отображать ошибки обновления, не переводя исправный VPN в состояние ошибки подключения. Дополнительная кнопка принудительного обновления в первую версию не требуется.

## Обновление и хранение списков

Для активного режима формировать `type: remote`, `format: binary`, исходный `url`, абсолютный `initial_path`, `update_interval: 1d` и явный `http_client.detour: proxy`. Включить `experimental.cache_file.enabled` и постоянный `cache.db`. Эти поля опираются на [rule-set](https://sing-box.sagernet.org/configuration/rule-set/), [HTTP Client](https://sing-box.sagernet.org/configuration/shared/http-client/) и [Cache File](https://sing-box.sagernet.org/configuration/experimental/cache-file/); `initial_path` и `http_client` требуют sing-box 1.14 или новее.

Жизненный цикл:

1. При установке включить все 22 `.srs`: 21 RoscomVPN и один Russia inside. Хранить встроенную копию отдельно от кэша загрузок.
2. При запуске sing-box использует подходящий валидный кэш, при его отсутствии — встроенный файл. Первый запуск не должен требовать успешной загрузки списков из интернета.
3. Обновления выполняет само ядро, пока VPN подключён. Если сохранённый интервал истёк, оно проверяет обновление после запуска; отсутствие кэша с загрузкой встроенного списка также не должно откладывать первую фоновую проверку на сутки.
4. Успешно проверенный список применяется без переподключения VPN. Обновления независимы: ошибка одного списка не отменяет обновление остальных.
5. Сетевая ошибка, HTTP-ошибка или повреждённый `.srs` не заменяют последний валидный список. В журнал попадает причина; VPN продолжает работать с доступными правилами.
6. Перезапуск приложения, смена режима и повторное копирование встроенных файлов не стирают загруженный кэш. Обновление приложения также сохраняет кэш и профиль.
7. При отключённом VPN списки не скачиваются и VPN ради этого автоматически не включается. Следующее подключение возобновляет штатный цикл ядра.

Пример дескриптора, где абсолютный путь вычисляется приложением:

```json
{
  "type": "remote",
  "tag": "geosite-github",
  "format": "binary",
  "url": "https://raw.githubusercontent.com/hydraponique/roscomvpn-geosite/release/sing-box/github.srs",
  "initial_path": "C:\\ProgramData\\SingVpn\\rulesets\\initial\\geosite-github.srs",
  "update_interval": "1d",
  "http_client": { "detour": "proxy" }
}
```

Загрузка должна обходить бизнес-правила через явный `detour: proxy`, в том числе для GitHub в режиме Russia inside. Использовать обычную проверку HTTPS-сертификатов и штатные HTTPS-переадресации GitHub Releases. Ошибка загрузки через VLESS не должна вызывать скрытый повтор напрямую.

Если отсутствуют и валидный кэш, и встроенный файл обязательного списка, сообщить об ошибке ресурсов и не запускать режим с незаметно урезанными правилами. Повреждённую БД кэша изолировать в отдельный файл, один раз повторить запуск со встроенными списками; не удалять профиль и не зацикливать восстановление.

## TUN и DNS на Windows

Полный конфиг генерируется приложением: входной TUN, VLESS outbound `proxy`, outbound `direct`, DNS, выбранный route и кэш. Импортированная ссылка определяет только параметры сервера, транспорта и TLS. Она не меняет DNS, inbounds, роутинг и источники обновлений.

Использовать Windows TUN sing-box с `auto_route: true`, `strict_route: true`, `dns_mode: hijack` и `route.auto_detect_interface: true`. Для первой версии явно выбрать `stack: system`; MTU по умолчанию 1500. Адреса TUN IPv4/IPv6 задаёт приложение из проверяемых приватных диапазонов; конфликт с уже существующей сетью должен завершаться понятной ошибкой, а не изменением чужого интерфейса. Платформенные поля сверять с [TUN inbound](https://sing-box.sagernet.org/configuration/inbound/tun/) версии 1.14.2; не копировать настройки Apple Network Extension или Linux `auto_redirect`.

Сохранить базовую DNS-политику переданного VLESS-кода:

- Основной DNS — UDP `1.1.1.1`, тег `dns`, через `proxy`; `dns.final: dns`, стратегия `ipv4_only`.
- Bootstrap DNS — UDP `1.1.1.1`, тег `bootstrap`, напрямую через физический интерфейс. Для доменного адреса VLESS задать `domain_resolver` на `bootstrap`, без зависимости от ещё не установленного туннеля.
- Для доменов, нужных самому outbound `direct`, также явно определить разрешение через bootstrap и физический интерфейс, чтобы отсутствие туннеля не создавало DNS-цикл.
- При IP-адресе сервера DNS для его разрешения не требуется, включая IPv6-литерал. Стратегия `ipv4_only` относится к разрешению имён, а не к запрету IPv6-адреса сервера.
- В режиме Russia inside дополнительно включить reverse mapping. Переключение роутинга не должно менять основной DNS.

Для определённой границы первой версии пользовательский трафик обслуживается по IPv4. IPv6 захватывается TUN и отклоняется явным платформенным правилом после перехвата DNS и до бизнес-правил обоих режимов; ему нельзя незаметно обходить VPN через физический интерфейс. Это дополнение к Apple-политике должно быть отдельно покрыто тестами. Системный IPv6 глобально не отключать. Полноценная IPv6-маршрутизация пользовательского трафика относится к последующей версии.

После отключения, неудачного запуска и падения ядра восстанавливать только изменения, принадлежащие приложению: TUN, маршруты, DNS и связанные фильтры. Не выполнять глобальный сброс сети или firewall. `strict_route` не заменяет kill switch: после остановки VPN обычное соединение Windows восстанавливается. При недоступности сервера во время работающего ядра правила `proxy` не переключаются автоматически на direct; явно заданный direct продолжает следовать политике режима.

## Данные и эксплуатация

Профиль хранить в пользовательском LocalAppData, шифровать Windows DPAPI в контексте текущего пользователя. Полную исходную ссылку отдельно не сохранять: достаточно нормализованных полей. Сохранение атомарное, со `schemaVersion`; выбранный режим хранить отдельно от секретов.

Служба получает расшифрованный профиль по защищённому pipe только для подключения. Runtime JSON и рабочие файлы размещать в ProgramData с ACL для службы/System и администраторов; runtime JSON содержит UUID, его не включать в диагностику и удалять после завершения сессии. Кэш списков размещать отдельно от временного конфига, чтобы очистка сессии не уничтожала обновления.

Все операции подключения и смены режима сериализовать в службе. Для дочернего ядра использовать контролируемое завершение и Windows Job Object либо эквивалент, исключающий осиротевший процесс после аварии службы. При потере сети показывать её состояние; после возвращения сети разрешить одну попытку восстановления текущего подключения. Новая попытка пользователем и явное отключение имеют приоритет над автоматическим восстановлением.

Журнал содержит время, уровень, источник и сообщение; по умолчанию — `info`. Предусмотреть поиск, паузу, очистку и экспорт текстового файла. Ограничить хранение, например пятью файлами по 5 МиБ. До записи и экспорта исключать исходные URI, UUID и другие секреты, включая те, которые может содержать stderr ядра. Обычный журнал не должен подробно записывать историю посещаемых доменов. В диагностике указывать версии приложения/ядра, выбранный роутинг и ошибки службы, TUN, DNS и rule-set.

## Сборка и установка

Создать отдельное Windows-решение, не добавляя Windows-зависимости в Swift-targets. Организация может включать UI, службу, общие типы/генерацию конфигурации, ресурсы роутинга и тесты; не создавать отдельные подсистемы без необходимости.

Установщик должен:

- Поставлять UI, службу, закреплённый официальный `sing-box.exe` и необходимые для выбранной сборки компоненты Windows TUN. Их фактический состав проверить на чистой машине; не требовать ручного скачивания DLL пользователем.
- Включать встроенные `.srs`, лицензии и сведения о версиях. Для артефактов ядра зафиксировать версию, происхождение и SHA-256 в манифесте сборки.
- Запрашивать UAC для установки/удаления службы и системных компонентов; ежедневная работа UI не требует запуска от администратора.
- При обновлении сохранять профиль и rule-set кэш, а при удалении сначала останавливать VPN и удалять принадлежащие приложению сетевые ресурсы. Удаление сохранённых пользовательских данных предлагать отдельной опцией.

Не переносить бренд, bundle ID, Apple entitlements, скрипты сборки Libbox, отчёты памяти iOS и retired-интерфейс из `ApplicationLibrary/` как обязательные функции. Оформление адаптировать под Windows: масштабирование 100–200%, клавиатурная навигация, screen reader, светлая/тёмная тема; статусы различимы не только цветом.

В поставке сохранить уведомления и лицензионные тексты используемых проектов. Для переносимого кода Apple-проекта и ядра ориентироваться на их `LICENSE` и условия выбранных артефактов; включить необходимые исходники и инструкции воспроизводимой сборки. Отдельно учесть лицензии списков и TUN-компонентов.

## Проверки и критерии приёмки

### Автоматические проверки

| Область | Обязательные сценарии |
| --- | --- |
| Импортер | TCP без TLS, TCP/TLS, TCP/Reality/Vision, WS/TLS, gRPC/TLS, варианты без TLS для WS/gRPC, IPv4, домен, IPv6, Unicode-имя, `%26` в path, буквальный `+` |
| Ошибки импорта | Пустая/слишком длинная строка, неверный UUID/порт/encoding, повтор query-ключа, несколько ссылок, подписка вместо VLESS, неизвестный параметр/транспорт, отсутствующий Reality key, несовместимый flow, insecure |
| Конфигурация | Результат `sing-box check` для всех поддерживаемых комбинаций обоих режимов; отсутствуют TURN-зависимости, неопределённые outbound и исторический тег `vk-wg` |
| Роутинг | Сравнение структуры с исходным `routing.json` после разрешённых замен тегов/путей и добавления IPv6-защиты; порядок правил, 21 + 1 список, правильный `final` обоих режимов |
| Обновления | Чистый кэш и встроенный список; успешная загрузка; HTTP 304; HTTP-ошибка; повреждённый `.srs`; сохранение последнего валидного содержимого после рестарта; изоляция повреждённого кэша |
| Направление загрузок | Локальный тестовый proxy подтверждает загрузку rule-set через `proxy`; ошибка proxy не вызывает direct-запрос |
| Состояния | Повторный Connect, отмена запуска, тайм-аут остановки, смена роутинга, ошибка нового режима, ограниченный откат, переподключение UI к службе |
| Контракт службы | Отказ чужому SID, неподдерживаемому режиму VK TURN и попытке передать произвольные пути/команды; секреты отсутствуют в статусах и журналах |

Тесты парсера и генератора не используют реальные пользовательские ссылки. Для сетевых сценариев использовать контролируемый тестовый VLESS-сервер. Тесты обновления должны подтверждать поведение выбранного официального ядра, а не только форка из переданных исходников.

### Проверка на Windows

На чистых Windows 10 и Windows 11 x64 выполнить установку, импорт, подключение, отключение, обновление и удаление. Проверить два физических интерфейса, Wi-Fi/Ethernet, переход между сетями, сон/пробуждение, отсутствие сети при старте и восстановление после падения ядра/службы.

Проверить реальные маршруты и DNS до подключения, во время работы и после остановки. Для RoscomVPN подтвердить proxy/direct/reject и запрет YouTube UDP/443; для Russia inside — proxy по списку и direct вне списка. Использовать контролируемые тестовые rule-set для пересечений и затем smoke-проверку встроенных списков; изменяющийся публичный домен не должен быть единственным доказательством маршрутизации.

Отдельно проверить: первый запуск с недоступными источниками списков; применение валидного обновления без обрыва VPN; отказ от повреждённого обновления; IPv6 без обхода TUN; DNS при двух активных адаптерах; bootstrap доменного VLESS-сервера без цикла; сохранение рабочего кэша после обновления программы. Учётные данные для успешного end-to-end теста предоставляет тестовый сервер, в репозиторий их не добавлять.

Первая версия принимается, когда:

1. Пользователь без сервера подписок импортирует поддерживаемую `vless://` ссылку и подключает системный VPN.
2. VK TURN остаётся видимым переключателем с пометкой «В разработке», недоступен и не имеет рабочей транспортной реализации.
3. Оба встроенных роутинга соответствуют описанным политикам, сохраняются и корректно применяются при переподключении.
4. Списки обновляются через VLESS раз в сутки при активном VPN; встроенный fallback и постоянный кэш обеспечивают работу без успешной загрузки.
5. Ошибки импорта/обновления не уничтожают рабочие данные; ошибки ядра не оставляют бесконтрольные процессы и сетевые изменения.
6. Сборка воспроизводима по README Windows-проекта; поставлены установщик, исходники, тесты, журнал выполненных проверок, версии и лицензии зависимостей.

## Порядок реализации

1. Создать Windows-решение, закрепить ядро и ресурсы; реализовать и проверить импортер VLESS и генератор конфигурации.
2. Реализовать службу, защищённый IPC, запуск/остановку sing-box, TUN и восстановление сетевого состояния.
3. Перенести оба режима маршрутизации и проверить нативные обновления, кэш и fallback на официальном ядре.
4. Реализовать экраны, неактивный VK TURN, состояния подключения, трей и журнал.
5. Подготовить установщик и провести приёмочные проверки на чистых Windows 10/11.
