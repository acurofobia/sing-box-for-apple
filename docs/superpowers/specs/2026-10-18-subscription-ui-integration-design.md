# Подключение интерфейса iOS к серверу подписки

Исторический документ. Старый `subscription-server/` удалён из проекта 25 октября 2026; актуальный сервер разрабатывается в отдельном репозитории `acurofobia/subscription-ui-server`. Исходники Sketch хранятся локально.

Дата: 2026-10-18. Статус: спецификация для подтверждения перед реализацией.

## Цель и границы

Приложение получает VPN-параметры и содержимое интерфейса через одну вводимую
пользователем ссылку подписки. Основные экраны соответствуют Sketch, а данные
готовых компонентов приходят из JSON с обезличенными идентификаторами.
Кнопки, поля, навигация, системные окна и списки максимально используют SwiftUI
и нативное поведение iOS. Верхняя шторка выбора режима сохраняет расположение
и направление раскрытия из Sketch.

Изменяется текущий iOS target `SFI`, схема `VKTurnPrototype`, исходники
`PrototypeApp/`. В настройках target сейчас указан iOS 27.0; понижение версии
в эту задачу не входит. macOS и tvOS не изменяются. На iPad используются
адаптивная компоновка и системные варианты презентации.

Сохраняются существующие VLESS, VK TURN, роутинг, работа расширения и логи.
Автоматический выбор транспорта не реализуется. Платежи и личный кабинет
открываются внешними ссылками; приложение не реализует их серверную логику.

## Решения пользователя

- Пользователь вводит одну ссылку для VPN и интерфейса.
- Выбор режима остаётся верхней шторкой, как в Sketch.
- Обновление подписки запускается при старте, возвращении приложения
  в активное состояние и по кнопке «Обновить». Постоянного опроса сервера нет.
- Из прежних технических инструментов в интерфейсе остаются только логи.
  Ручной импорт, ввод VK TURN, экспорт CSV и отчёты памяти убираются из UI.
- Запрет режима в свежих данных не прерывает уже установленное соединение
  и не включает другой режим автоматически; следующий запуск запрещён.
- При первом добавлении и замене подписки нужно успешно загрузить весь
  комплект данных. Экран с неполученным оформлением не позволяет запуск VPN.
- После успешной настройки при недоступном сервере разрешена работа
  по последнему сохранённому комплекту с сообщением об ошибке обновления.
- «Авто» остаётся недоступным и отображается как находящееся в разработке.
- На начальном экране пока нет кнопки «Где взять ссылку?».
- «Изменить» на главном экране переключает вкладку на «Профиль».
  «Изменить тариф» в профиле выполняет серверное действие кнопки карточки.

## Одна ссылка и два источника данных

Пользователь по-прежнему вводит адрес действующего endpoint
`/subscription/<token>`. Его ответ сохраняет `sing_box_url`, `vk_turn_link`
и дополнительно содержит:

| Поле | Значение |
|---|---|
| `ui_url` | Абсолютный адрес `/v1/subscription` сервера UI |
| `ui_token` | Bearer-токен для этого endpoint либо null для локального доступа без токена |

Эти два поля — выбранное техническое расширение ответа, а не названия
интерфейсных блоков. Существующий JSON интерфейса версии 1 не меняется.
Действующий сервер получает адрес и токен UI из `UI_DOCUMENT_URL`
и `UI_DOCUMENT_TOKEN`; реальные значения не попадают в Git.

Первичное подключение выполняется так:

1. Проверить введённую ссылку и получить ответ VPN-сервера.
2. Получить VLESS-конфигурацию, если указан `sing_box_url`, и проверить
   VK TURN, если указан `vk_turn_link`, по существующим правилам импортера.
3. Получить UI-документ по `ui_url`; при наличии `ui_token` отправить
   `Authorization: Bearer <ui_token>` только этому endpoint.
4. Проверить весь UI-документ и клиентские привязки, затем одним действием
   сохранить полный комплект и открыть основные вкладки.

HTTP-ошибка или некорректный UI-документ не оставляют частично применённую
подписку. На первом запуске форма остаётся доступной с понятной ошибкой
и повторной попыткой. При замене ссылки старый комплект сохраняется до
успеха нового. Для применения другой ссылки работающий VPN сначала нужно
отключить; форма объясняет это ограничение.

Если транспорт намеренно отключён сервером или его отдельные параметры
некорректны, сохраняется существующее поведение импортера: предупреждение
и недоступность этого транспорта. Это не отменяет требование получить
UI-документ. Подписка без доступных транспортов открывает основные экраны,
но подключение недоступно и показана причина.

Ссылки `ui_url` нет в старых ответах. Такой ответ не считается полным новым
комплектом: приложение сообщает, что сервер нужно обновить. Работавший ранее
туннель из-за этого не отключается. Прямой URL нового UI-сервера не заменяет
ссылку VPN-подписки: в нём нет параметров подключения.

Для iPhone адрес UI должен быть доступен с телефона, например имя Mac
в локальной сети; `127.0.0.1` телефона не указывает на Mac. Адреса и токены
не вшиваются в приложение. Локальный HTTP разрешается существующей
настройкой доступа к локальной сети; публичное размещение использует HTTPS.

## Получение данных и сохранение

UI загружается с ограничением 1 MiB и таймаутом 10 секунд. Перенаправления
не принимаются, токены не пересылаются на другие URL. Успехом считается HTTP 200.
Нельзя сначала без ограничения загрузить весь ответ, а затем проверить размер:
лимит применяется при чтении тела. Ограничения VPN-конфигурации сохраняются.

Комплект включает исходный URL, проверенные параметры VPN, UI-документ,
параметры доступа к нему и локальное время успешного обновления. Он сохраняется
атомарно с существующей защитой файла в App Group. Секреты не записываются
в UserDefaults, fixtures, скриншоты тестов, сообщения ошибок или логи.

Автоматическое обновление и «Обновить» используют одну операцию. Одновременно
работает не больше одной загрузки; ответы предыдущей ссылки или отменённого
запроса не могут заменить новую подписку. При ошибке сохраняется предыдущий
полный комплект, показываются ошибка и время последнего успешного обновления.
Текущий экран не заменяется пустым состоянием во время обычного обновления.

Обновление при подключённом VPN может получить и сохранить новый полный
комплект, но не переписывает runtime-файлы, не очищает активные credentials
и не перезапускает туннель. Новые VPN-параметры применяются при следующем старте.
Новые тексты и ограничения UI отображаются сразу после успешной проверки.
Это требует отделить сохранение подписки от текущего `save`, который требует
отключения и очищает runtime. Действие «Отключить» доступно и во время загрузки.

Односекундное получение существующего статуса расширения не является опросом
сервера подписки и может продолжаться отдельно.

Существующий кэш без UI-документа сохраняется при миграции, но не даёт права
на новый запуск VPN до получения полного комплекта. Уже работающий туннель
продолжает работу, а приложение позволяет его отключить.

## Привязка обезличенных блоков

В приложении фиксируются только структурные типы, слоты экранов, постоянные
идентификаторы и поддерживаемые действия. Бизнес-смысл текста не определяется
по словам «Баланс», «Тариф» или названию режима.

| ID и тип | Размещение и поведение |
|---|---|
| `block01`, `card` | Общие данные карточки главного экрана и профиля |
| `block02`, `valueRow` | Крупное значение, подпись и кнопки в профиле |
| `block03`, `actionSheet` | Выбор внешней ссылки личного кабинета |
| `block04`, `selectionList` | Содержимое верхней шторки выбора режима |
| `block05`, `menu` | Серверные пункты профиля |
| `block06`, `progress` | Полоса числового значения на главном экране |
| `page01`, `page02` и другие страницы | Текстовые внутренние страницы по ID |

На главном экране `block01.title`, `subtitle`, `text` приходят с сервера,
но нижняя кнопка «Изменить» — локальная навигация в профиль. Она не использует
действие `button01`. В профиле показываются серверные `block01.buttons`
с их текстами и действиями. Надпись «Подписка», «Обновить» и дата обновления
остаются локальными. Фон карточки и размеры шрифтов берутся из макета,
не передаются сервером.

`visible: false` скрывает элемент вместе с отступами. Отсутствие необязательного
блока скрывает его слот. Отсутствие `visible` означает true. Все полученные
элементы, включая скрытые, проверяются по контракту сервера.
Известный ID с неправильным типом делает обновление некорректным.
Новые неизвестные ID блоков не размещаются самопроизвольно на экранах.

Порядок кнопок и пунктов сохраняется из JSON. В `block05` локальные «Логи»
и «Настройки приложения» вставляются перед `item03`; если такого ID нет,
добавляются после серверных пунктов. При отсутствии или скрытии `block05`
локальные строки остаются доступными отдельной группой.

`block06` показывает серверные `value`, `maximum`, `unit`, `period`, `resetAt`.
Приложение форматирует значения и прогресс; эти числа не смешиваются
с текущей скоростью или счётчиками соединения. Локальная кнопка «Обновить»
возле прогресса вызывает общую загрузку подписки.

Клиент проверяет версию 1, типы, размеры, уникальные ID, диапазоны чисел,
ссылки страниц и действий по спецификации сервера. Некорректное обновление
отвергается целиком. `pages[].text` — обычный текст, без HTML или WebView.

## Режимы и действия

| ID варианта | Техническая привязка |
|---|---|
| `option01` | VLESS |
| `option02` | VK TURN |
| `option03` | Недоступный «Авто» |

Имя режима берётся из `title` во всех местах его отображения, включая верхнюю
строку и VPN-карточку. Техническая привязка не меняется при переименовании.
Выбрать и запустить режим можно, только если он видим, серверное состояние
`available`, реализация поддерживается клиентом и корректный конфиг получен.
Сервер не может включить «Авто» значением `available`.
Неизвестные варианты показываются недоступными с локальным объяснением.

Для `restricted` показываются `stateText` и серверные кнопки вместо ссылки
«Подробнее». Для `unavailable` показываются пояснение и состояние без выбора.
У доступного варианта `detailsPageId` открывает соответствующую внутреннюю
страницу. Если ID равен null, ссылки «Подробнее» нет.

Если выбранный режим запретили или скрыли во время соединения, он сохраняется
как фактически работающий, показывается предупреждение, а «Отключить» остаётся
доступным. После отключения повторный запуск запрещён. Другой режим выбирает
пользователь. При первом подключении без сохранённого выбора выбирается первый
доступный поддерживаемый вариант по порядку JSON.

Переключение подключённого VPN по явному выбору пользователя сохраняет
существующую последовательность остановки и запуска. На переходных состояниях
повторный выбор блокируется; выбор уже активного варианта не перезапускает VPN.

Действия обрабатываются единым диспетчером:

- `openExternalUrl`: открыть проверенную HTTPS-ссылку системным способом;
  universal link может открыть Telegram, остальные ссылки — браузер.
- `openScreen` с `screen01`: открыть нативную форму изменения подписки.
- `openBlock`: открыть описанный `actionSheet` по ID.

Неизвестные внутренние экраны не запускают произвольные операции; приложение
сообщает, что действие не поддерживается. Внешние URL не используются для
исполнения кода или конфигурирования VPN. Пользователь может отменить любое
окно выбора без изменения данных.

## Экраны и нативные компоненты

Основная навигация — системный `TabView` с вкладками «Подключение», «Роутинг»,
«Профиль». Каждая вкладка сохраняет свою навигацию через `NavigationStack`.
Акцентный цвет, фон карточки подписки, иерархия текста и расположение основных
элементов соответствуют Sketch. Системный tab bar не заменяется нарисованной
копией ради точного совпадения с импортированным Apple-символом.

| Состояние Sketch | Реализация |
|---|---|
| `00` и `00а` | Начальный экран с нативным URL-полем, «Вставить», «Добавить подписку» |
| `00б` | Пока недоступно, поскольку «Где взять ссылку?» скрыто |
| `01` и `04` | Главный экран, компактная VPN-карточка |
| `02` и `05` | Тот же экран с раскрытой VPN-карточкой |
| `03` | Открытая верхняя шторка режимов |
| `03а` | Та же шторка с ограниченным вариантом и серверной кнопкой |
| `06` | Профиль с карточкой, строкой значения и группой меню |
| `07` | Нативное окно выбора внешней ссылки |

Форма подписки использует URL-клавиатуру, отключённые автозамену
и автокапитализацию, индикатор загрузки и системные кнопки. «Вставить»
использует нативный механизм вставки. Во время загрузки повторное добавление
блокируется. Ошибка сохраняет введённый текст и позволяет повторить попытку.

Начальное добавление находится на отдельном экране до основных вкладок.
`screen01` открывает ту же форму в системном sheet с `NavigationStack`,
«Отмена» и действием сохранения. Текущая рабочая подписка не исчезает
при отмене или ошибке замены. Сохранять другую ссылку можно после отключения VPN.

Личный кабинет показывается нативным `confirmationDialog` с серверными
заголовком, пояснением и действиями; «Отмена» локальная. На iPad допускается
системное представление popover. Различия размеров и типографики системного
диалога относительно Sketch принимаются ради нативного поведения.

Страницы «Подробнее» открываются системным sheet с `NavigationStack`,
прокручиваемым текстом, кнопкой закрытия и системным жестом закрытия.
Высота адаптируется к содержимому; для длинного текста доступны medium/large.
Настройки и логи открываются обычными переходами `NavigationStack`.
В настройках нет скрытых технических форм, ручного импорта или CSV;
системные настройки приложения открываются стандартным способом.

Роутинг использует существующий нативный экран и сохраняет его функциональность:
режимы, сохранение, реальные правила, DNS и переподключение по явной смене.
Макет отдельного нового экрана роутинга в Sketch отсутствует, поэтому его
визуальное переизобретение в эту задачу не входит.

## Верхняя шторка и анимации

Верхний выбор режима — единственное модальное представление с собственным
контейнером. Внутри используются нативные кнопки, текст и доступные элементы
выбора. Закрытая строка привязана к верхней безопасной области экрана.
Открытие увеличивает её высоту вниз; верхняя кромка остаётся на месте.
Закрытие выполняет обратное движение, а не простое исчезновение содержимого.

На эталонном экране 390×844 ориентиры Sketch: закрытая строка 52 pt,
открытая шторка около 456 pt, вариант с ограничением около 498 pt.
Это ориентиры для обычного размера шрифта, не жёсткие высоты: длинные тексты,
Dynamic Type и небольшой экран требуют прокрутки внутри доступной высоты.

Открытие запускается нажатием строки либо жестом вниз за ручку; закрытие —
стрелкой, нажатием на затемнение или жестом вверх. Движение связано с жестом,
после отпускания шторка плавно завершает открытие или закрытие. Используется
системная spring-анимация SwiftUI около 0.3 секунды без сторонних библиотек.
Затемнение изменяется синхронно; нижележащие кнопки и tab bar не принимают
нажатия, пока шторка открыта. Быстрые повторные нажатия не создают копии шторки.

VPN-карточка — отдельный элемент внутри экрана. Она раскрывается вверх,
сохраняя нижнюю границу, без затемнения и модальной блокировки. Ориентиры
Sketch: высота 198 → 418 pt при ширине 354 pt. Кнопка «Подробнее» в этой
карточке раскрывает показатели, а ссылка в выборе режима открывает страницу:
это разные действия. Собственная анимация не применяется поверх системного sheet.

Координатор презентаций не допускает одновременного открытия верхней шторки,
системного sheet и диалога. Перед открытием страницы из шторки сначала
завершается её закрытие; внешний переход запускается после закрытия диалога.
Обновление JSON во время анимации не меняет идентичность представления
и не сбрасывает жест. Если показанный элемент удалён, окно штатно закрывается.

При включённом Reduce Motion пространственные перемещения заменяются коротким
плавным переходом. Для VoiceOver предусмотрены название, текущее состояние,
объявление выбранного варианта, модальный фокус и действие закрытия.
Области нажатия не меньше 44×44 pt; смысл состояния не передаётся одним цветом.

## Показатели VPN

Состояние, длительность, выбранный режим и память берутся из приложения
и расширения. Данные сервера подписки не подменяют состояние туннеля.
Пинг, сервер, маршрут, трафик и скорости в раскрытой карточке используют
реальные доступные данные существующего ядра. Пока значение не получено,
показывается «—»; значения из демонстрационного Sketch не используются.
Добавление новой системы измерений, отдельного VPN-процесса или опроса
сервера подписки ради этих показателей не входит в изменение интерфейса.

## Техническая организация изменений

Это выбранные проектные решения, которые нужно проверить на реализации:

- Сохранить `PrototypeModel` как владельца жизненного цикла VPN. Вынести
  описание и проверку UI-документа в отдельные Codable-типы и сервис загрузки.
- Отделить состояние загрузки подписки от состояния подключения, чтобы
  фоновая загрузка не блокировала отключение VPN.
- Выделить представления главного экрана, профиля и верхней шторки,
  переиспользовать одну карточку с явным контекстом экрана.
- Использовать enum для вкладки и презентации; не создавать набор
  независимых boolean, допускающих несколько модальных окон одновременно.
- Не добавлять стороннюю библиотеку UI, анимаций или сетевого доступа.
- Сохранить существующие ограничения импортера VLESS: один подходящий
  outbound, без импорта чужих route/DNS/inbounds и без detour.
- Дополнить пример ответа и тесты действующего VPN-сервера полями UI;
  обновить документацию обоих серверов. Не переписывать пользовательские
  `.env`, конфиги VPN, токены и макет Sketch.
- Нужные новые локальные строки добавить в локализацию приложения.
  Серверные строки показывать как полученный текст.
- Не менять bundle ID, App Group, подпись, entitlements и minimum iOS.

## Критерии приёмки

### Контракт и жизненный цикл

Проверки на локальных управляемых ответах без реальных credentials:

1. Одна ссылка загружает параметры VPN и авторизованный UI-документ.
2. Первый запуск и замена не сохраняют частичный результат при ошибке любой
   сетевой загрузки или UI-валидации; введённый URL остаётся доступным.
3. Успешный комплект сохраняется после перезапуска. Недоступность сервера
   сохраняет его и разрешает VPN по согласованному офлайн-поведению.
4. Изменение JSON становится видно после трёх согласованных триггеров.
   Нет постоянных запросов к серверу или конкурирующего применения ответов.
5. Обновление во время подключения не меняет работающий туннель, а запрет
   текущего режима применяется к следующему запуску.
6. Проверяются размеры, дубли ID/ключей, некорректные ссылки, неизвестная
   версия, неправильные типы известных блоков и скрытые некорректные элементы.
7. Название режима не влияет на его техническую привязку; «Авто» нельзя
   активировать через JSON. Нет автоматического перехода на другой режим
   после запрета уже выбранного.
8. Ни ошибки, ни логи не раскрывают URL подписки с токеном и содержимое конфигов.

### Интерфейс и взаимодействие

На симуляторе и при доступности на физическом iPhone проверить:

1. Все реализуемые состояния Sketch из таблицы, включая подключённый
   и отключённый VPN, обе высоты карточки и ограниченный вариант режима.
2. «Изменить» переключает вкладку; «Изменить тариф» выполняет серверное
   действие; `screen01` открывает форму, `block03` — выбор Telegram/сайта.
3. Редактирование title/subtitle/text/button title/URL в JSON меняет
   соответствующие элементы без сборки приложения и без смены их ID.
4. Верхняя шторка движется вниз при открытии и вверх при закрытии; проверены
   ручка, scrim, быстрые нажатия и отсутствие нажатий сквозь затемнение.
5. VPN-карточка сохраняет нижнюю границу; системные окна открываются
   штатными переходами и закрываются системными жестами.
6. Проверены длинные строки, пустые списки, скрытые блоки, Dynamic Type,
   VoiceOver, Reduce Motion, landscape и базовая адаптация iPad.
7. «Где взять ссылку?», технический импорт и CSV отсутствуют; логи доступны.
   Роутинг и явное переключение транспорта сохраняют прежнюю работу.
8. Подготовлены снимки до/после. Анимации проверены взаимодействием и при
   необходимости записью экрана; статичный скриншот не доказывает плавность.

Запустить релевантные Swift/Python тесты подписки и серверов, обновлённые
XCTest UI-тесты и сборку схемы `VKTurnPrototype` для доступного симулятора.
SwiftFormat/SwiftLint применять к изменённым Swift-файлам с конфигурацией проекта.
Сетевую работу туннеля подтверждать только на физическом устройстве;
симулятор используется для интерфейса и управляемых сетевых ответов.
